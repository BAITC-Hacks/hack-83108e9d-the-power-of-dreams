# P02 — Каталог и справочники

**Результат:** проверенный immutable-каталог и глобальные опции формы. **Владелец:** один backend-исполнитель. **Зависимости:** принятый P01. **Параллельно:** P03/P04, в пределах лимита. Общие правила: [план](README.md).

## Scope и контракт

- Ветка `codex/cs-02-catalog`; worktree `D:/Alem/hack-83108e9d-the-power-of-dreams-wt-cs-02`; base — общий SHA P01.
- Можно изменять только `back/catalog/` и расположенные там проверки. Чтение `raw/dataset.csv`, публичных `back/domain/types.ts` и закреплённых контрактных примеров. Сеть/серверный порт не нужны.
- Операция `loadCatalog(path)` и точные выходы/ошибки берутся из P00/OpenSpec. Модуль владеет CSV decoding, проверкой записи и snapshot; filesystem-path передаёт composition.
- Допустимые зависимости: filesystem, согласованный CSV-парсер, существующая валидация, публичные plain types. Нет AI, HTTP, React, алгоритма отбора или чтения секретов.
- Не менять CSV, shared types, package/lockfile, `back/composition.ts`, routes и соседние модули. Потребность в общей правке сообщить координатору.

## Задачи

1. Сверить реализацию P01 с [контрактом исходных данных](../domain/data-contract.md); доработать только отсутствующее.
2. Корректно читать кавычки/запятые CSV, pipe-списки, boolean flags, пустой `max_hours` → `null`, строковые IDs и даты. Не исправлять/выдумывать профиль молча при повреждении данных.
3. Проверять структуру и необходимые значения, уникальность IDs; ошибки отдавать через согласованный безопасный typed failure из [P00](00-foundation-and-contracts.md#отказ-однократной-загрузки-каталога). Недоступный или некорректный каталог не превращается в нормальную пустую выдачу. Loader не завершает процесс; сохранение отказа на процесс и HTTP 503 принадлежат composition/HTTP в P05.
4. Возвращать глобальные city/category/format/language options и окно календаря. Категория остаётся в глобальных опциях, даже если её нет в выбранном городе.
5. Сохранять исходные описания и флаги в server snapshot для допустимых потребителей; не превращать loader в публичный endpoint каталога. Snapshot не мутируется потребителями; повторное использование на процесс организует composition P05.

## Критерии и проверки

- Для текущего supplied snapshot: 66 уникальных профилей, 9 `max_hours: null`, корректные списки и флаги. Числа характеризуют эту поставку, не являются универсальным ограничением loader.
- Quoted comma не сдвигает колонки; pipe-membership точный; пустые часы не превращаются в 0 или «без ограничений».
- Файл отсутствует, повреждённая запись и duplicate ID дают предусмотренный отказ; отрицательные случаи на временных данных, оригинал неизменён.
- Чтение настоящего CSV + несколько целевых отрицательных случаев достаточно. Не создавать общий импортный фреймворк и тесты каждой частной функции.
- Команду проверок брать из P00/base, записать фактически выполненную и результат. HTTP 503 и загрузка один раз проверяются позднее в P05.

## Handoff

Вернуть принятые критерии, тестовый/commit SHA, текущий remote SHA при разрешённом push, contract revision, ограничения. Публикация только в разрешённых пределах task card. P05 получает модуль по публичной операции, без импорта decoder/validator internals. После принятия кандидат интегрирует координатор; исполнитель не меняет `main` и общие стадии.
