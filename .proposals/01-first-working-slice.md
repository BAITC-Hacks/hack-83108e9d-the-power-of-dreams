## Задачи

1. Сначала сверить существующие доказательства работоспособности `back/ai/openai.mjs`, не делать повторный транспорт. Его карточка уже фиксирует live plain-text probes и 6/6 contract checks; при совпадающих хешах и неизменном контексте использовать это evidence. Выполнить один реальный **domain** probe: описания трёх выбранных профилей плотного запроса, strict-ответ evidence, проверка источников и длительности. Plain-text probe эту проверку не заменяет. Чтение ключей и платные вызовы — только в рамках разрешённого implementation scope, через установленную границу secrets.
2. После двух содержательных неудач доступа/модели/сети/квоты зафиксировать причину. Разрешённый локальный degraded-путь можно продолжить; он не открывает gate успешного live MVP. NVIDIA не включать автоматически. Ручную замену единственного provider сначала оформить в OpenSpec и публичных mode labels.
3. Собрать минимальный реальный путь с [границами архитектуры](../architecture/system.md#proposed-code-boundaries): CSV загружается в памяти; чистый домен фильтрует и сортирует; evidence выбирается для максимум трёх; local renderer строит текст; thin HTTP передаёт контракт; простые форма/карточки в `front/` показывают ответ.
4. Реализовать только необходимое для плотного запроса и честного базового отказа, сохраняя замороженные операции. Не делать самостоятельный монолит-прототип, который P02–P06 должны будут переписывать. Функциональность P01 должна остаться частью MVP.
5. Проверить production build/start и October 10 в браузере, включая отсутствие server-only кода/секретов у клиента. Зафиксировать проверенный SHA и неизменяемые контракты для дальнейших модулей.

## Критерии и проверки

- Запрос: Алматы / Ведущий / корпоратив / `2026-10-10` / `1500000` KZT; язык/длительность не заданы.
- Из настоящего CSV: 10 кандидатов, 5 подходящих, карточки в порядке `HK-88430`, `HK-29829`, `HK-27222`. Это ожидаемые значения из [архитектурных сценариев](../architecture/implementation-and-verification.md#data-derived-rehearsal-cases), а не уже пройденный тест.
- Цены/поля принадлежат этим записям, объяснения с реально полученными и проверенными цитатами; видимый mode соответствует фактическому содержимому. При отказе AI данные отбора остаются настоящими, fallback обозначен.
- Один request проходит через реальные соединения модулей и HTTP; mock OpenAI отдельно проверяет отказ, но не засчитывается за live.
- Записать время до видимого результата и по каждой dense-карточке оценку по [live-критериям P00](00-foundation-and-contracts.md#минимальная-live-проверка-ai), включая причину релевантности и различимость при скрытых именах. Это предварительная dense-проверка; rare и весь итоговый набор ещё предстоят. Измерение одного запроса не заменяет итоговые три uncached-запроса P07.
