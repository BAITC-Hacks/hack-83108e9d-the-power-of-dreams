# P06 — Форма, результаты и смена даты

**Результат:** законченный основной экран с честными состояниями и объяснением изменения выдачи. **Владелец:** один frontend-исполнитель. **Зависимости:** P05 и точный backend/package snapshot. **Параллельно:** подготовка run-документации P07. Общие правила: [план](README.md).

## Задачи

1. Доработать экран P01: обязательные поля, optional language/duration, справочники и календарное окно из API. Глобально валидная категория не исчезает из списка из-за выбранного города.
2. Показать loading/field validation/service error, три нормальных исхода, partial result и фактические причины. Карточки содержат имя, выбранную категорию, город, цену «от», 1–2 предложения, корректную оговорку о календаре и quality flags.
3. Показывать реальный explanationMode, включая «Часть объяснений сформирована без ИИ» для mixed. Не называть AI-качеством детерминированный price/ID порядок; не трактовать `synthetic` как признак добавления командой.
4. Хранить предыдущий **успешный** normalized request/cards/busy IDs и context snapshot. Сравнивать результаты только при изменении одной даты и одинаковом catalogue/policy context; при reset очистить историю. Error/stale response не заменяют успешный snapshot.
5. На смене даты различать: предыдущий стал busy; новый был busy и стал доступен; прежний остаётся доступным, но вытеснен по цене/ID; уже доступный продвинулся из-за занятости других. Не выводить причины только по busy count. Пользоваться фактами и [правилами сравнения](../architecture/selection-and-explanations.md#explaining-date-changes), не реализовывать backend selection в браузере.
6. Не допускать дублирующий submit одного запроса; новый актуальный submit отменяет ожидание предыдущего. Stale result не может заменить карточки или comparison snapshot. Проверить keyboard focus и мобильную читаемость.

## Критерии и проверки

- На реальном pinned backend: dense/rare/no_match/category_absent, HTTP-ошибка, optional validation, live/fallback mode. Fixtures только для отдельно обозначенных редких UI states, не вместо интеграции.
- October 10 → 11: объяснение изменения занятости. October 1 → 6: `HK-29829` входит после снятия busy mark, `HK-75012` вытесняется по стартовой цене и **не называется занятым**.
- Дополнительно controlled public-contract examples проверяют продвижение уже доступного кандидата и равную цену с ID tie-break, без выдуманного «дешевле»/«лучше».
- Изменился другой вход/context, нет прошлого success, пришла ошибка или запоздалый ответ — нет ложного сравнения. При неизменных карточках нет выдуманной замены.
- Mixed/local labels совпадают с ответом и показанными объяснениями. Проверены desktop/mobile, клавиатура, фокус и читаемые ошибки в браузере.
- Зафиксировать реально выполненные browser steps/команды, pinned backend/package SHA, test/commit/remote SHA и пропуски.
